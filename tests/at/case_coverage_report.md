## 二、数据来源与统计口径

### 2.1 数据来源

- 原始基线：`tests/at/统信桌面操作系统 V25-用例.xlsx`「用例」sheet，共 2400 条，编号唯一。项目内无 `cases_raw.yaml`，以 xlsx 为准。
- AT 用例：`tests/at/yaml/` 下 71 个 `*.suite.yaml`，共 1178 个 suite case。来源关联优先取 `vars.xlsx_id`，其次取 `description` 中的「来源用例编号 / xlsx 用例编号」，再次取 case id 中数字。
- 过滤分类：沿用仓库既有 `.trellis/tasks/09-23-at-case-coverage-audit/research/raw-filter-audit.yaml`（基线 xlsx 未变化）。

### 2.2 弱覆盖 / 强覆盖 / 合并批次口径

- **弱覆盖（主口径）**：suite case 必须执行到原始用例对应的**功能入口、操作路径或关键控件**（UI 操作或等价的 CLI/DBus/配置命令），才计为覆盖；仅启动应用后断言预设 `PASS` 标记的「入口烟测」不计入主口径，单列为上界。
- **强覆盖**：suite case 必须执行原始关键操作，并断言原始预期中的关键最终结果，才计为覆盖。本报告不以此为准。
- **合并批次（PR #4567）**：新增 3 个 suite（68 条 case），以 `dde-file-manager <目录>` 打开夹具目录并断言 `PASS_<ID>`，未执行对应功能操作，按主口径不计覆盖，列入「入口烟测上界」；其覆盖了全部 208 条功能缺口。
- **场景化补全（PR #4568）**：新增 4 个 suite（本地合入 88 条），其中约 23 条含真实 UI 操作或功能脚本，其余仍为增强烟测，按主口径仅计入真实操作部分。

### 2.3 计数与排除规则

- **非 1:1 计数**：一个 suite case 可覆盖多个原始用例，按**原始用例条数**累计；同一原始用例被多个 suite case 覆盖只计一次。
- **不计功能弱覆盖**：① 仅启动应用/打开夹具目录并断言 `PASS_<ID>` 的入口烟测；② `steps` 为空仅断言预制 `PASS` 的伪用例；③ 仅断言进程存活或无关静态控件。
- 恒等式：`总数 = 过滤数 + 可自动化数`；`可自动化数 = 已覆盖数 + 待补数`。

## 四、弱覆盖统计

```
测试用例基线 2400
  ├─ 过滤（AT 无法完成） 1637
  └─ 可自动化数         763
        ├─ 已弱覆盖（功能操作口径） 612
        └─ 待补（功能操作口径）     151
        （入口烟测上界：763）
```

- 覆盖率 = 612 / 2400 = **25.50%**
- 可自动化覆盖率（主口径）= 612 / 763 = **80.21%**
- 可自动化覆盖率（入口烟测上界）= 763 / 763 = **100.00%**

### 4.1 AT 用例数（1178）多于转换对标数据（612）的原因

1. **同源拆分/变体**：363 条原始用例被拆成多个 suite case（同一原始 ID 多 case），故 AT 用例数大于原始用例数。
2. **映射到被过滤原有用例**：289 个 suite case 的原始 ID 属于过滤集合，不计入覆盖分子。
3. **无基线来源**：9 个 suite case（PR/动态效果等）不含 V25 编号。
4. **入口烟测未计主口径**：本次批次 68 条 case 仅打开夹具目录并断言 `PASS`，覆盖 208 条原始 ID 但未执行功能操作。
5. **一案覆盖多源**：120 个 suite case 同时关联多个原始 ID，按原始条数累计。

可自动化相关的 suite case 为 880 个，去重后功能弱覆盖 612 条原始用例。

### 4.2 新增批次 / 场景化用例复核（PR #4567、#4568）

**入口烟测（PR #4567）**
- `xlsx批次一批补全`（23）、`xlsx批次二批补全`（36）、`xlsx批次三批补全`（9），共 **68** 条，本地 68/68 通过。
- 步骤以 `session_start`（shell 造夹具 + `dde-file-manager <目录>`）+ `assert_element`（断言 `PASS_<ID>`）为主，未执行功能操作，按主口径不计覆盖；它们覆盖了全部 208 条功能缺口。

**场景化补全（PR #4568）**
- 4 个 suite：`xlsx场景化补全`（20/24 合入）、`二`（13/13）、`三`（14/14）、`四`（41/41），共合入 **88** 条，本地 88/88 通过。
- 其中约 23 条含真实 UI 操作（键盘/菜单）或功能辅助脚本，其余仍为「打开应用 + shell 断言」的增强烟测，按主口径不计覆盖。
- 净效果：将 **57** 条缺口从「仅入口烟测」提升为功能操作覆盖，功能弱覆盖由 555 升至 **612**，剩余功能缺口 **151** 条。

**未合入与修复**
- 未合入：`case_2018701`、`case_2018753`、`case_2018851`、`case_2018695`（智能语义搜索）——需要稳定的单窗口会话与搜索服务隔离，本机多次运行无法稳定通过。
- 已修复的确定性缺陷：回收站夹具改用 `$HOME`（`gio trash` 不支持 /tmp 挂载）、复制地址前先 `ctrl+a` 选择、排序/分组断言语义与夹具一致化、`session_start` 断言步骤避免 `sleep` 竞态。
